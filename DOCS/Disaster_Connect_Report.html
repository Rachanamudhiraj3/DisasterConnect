Project report

Disaster Connect: a small computer that warns you before trouble arrives

How the Local Disaster Watch system spots floods, earthquakes, storms and tsunamis, how it works even with no internet, and how we checked that it does its job.

September 2026 · Python, FastAPI, LangGraph, SQLite · runs on a Windows PC, shown in a phone-style web app

Abstract

Disasters do not wait for a good internet connection. We built a program that reads sensors every few seconds, checks them against safety limits for four dangers (flood, earthquake, storm and tsunami), and raises an alarm when a limit is crossed. The decision is made by simple, readable rules, so it is fast and can be explained. When the internet is available the program adds extras: live weather, nearby shelters and a friendly sentence explaining the alert. When it is not, the core alarm still works. We packaged everything into one zip file that runs by double-clicking. In our tests all 14 program parts loaded, every web address answered, and the storm and tsunami detectors fired correctly on test values.

1What problem are we solving?

Think about a smoke alarm. It is cheap, it sits quietly, and it does one job: it screams when there is smoke. It does not need Wi-Fi to do that.

Natural dangers are harder. A flood, an earthquake, a storm and a tsunami each show up in different ways, and when they hit, phone networks are often the first thing to fail. Our goal was a smoke alarm for many dangers at once, with three promises:

  • It keeps working offline. The alarm decision never waits for the internet.
  • It can explain itself. Every alert says why, for example “wind speed 120 km/h is above the limit of 70 km/h”.
  • It is easy to run. One zip, one double-click.

2The big idea in one minute

The system is like a school nurse with a checklist. Every few seconds she takes the readings (temperature, heartbeat, and so on) and compares them with the numbers on the checklist. If one is too high, she rings the bell. She does not guess. She follows the list, and she can always tell you which line on the list was crossed.

Our “nurse” is a set of four small programs called detectors, one for each danger. A fifth step picks the most serious result and sends the alert.

The pieces, in plain words

Sensors
Devices that measure the world: how high the water is, how hard it is raining, how fast the wind blows, how much the ground shakes. In our demo they are simulated by a program that makes realistic numbers, with an occasional dangerous spike.
Detectors (agents)
Four small rule-checkers. Each looks at the numbers for one danger.
Backend (FastAPI)
The waiter between the brain and the screens. The screens ask, “what is the risk right now?” and the backend answers.
Database (SQLite)
A notebook on disk. Every reading and every alert is written down so you can look back at history.
Screens
A phone-style web page with five views: Home, Shelter, SOS, Prediction and Report.

4How the program makes a decision

Each cycle follows the same steps. The readings go to all four detectors one after another. Then a “combine” step looks at their answers and picks the worst. Figure 2 shows the path.

An important safety rule: the risky decision is made only by the rules. The AI writer (a language model reached through the Groq service) is allowed to make the sentence friendlier, but it can never change “high” to “low”. If it fails or the internet is down, the plain rule sentence is used instead.

5The four detectors

Each detector has a limit taken from the settings file. Above the limit means “high”. The limits are stored in one place, so changing a number there changes it everywhere.

DangerWhat it watchesAlarm limitLike …
FloodWater level and rain ratewater 80 cm · rain 30 mm/hrWater creeping up the steps of a house.
EarthquakeGround shaking now, compared with the recent average3.0× the normalA quiet classroom that suddenly gets very loud.
StormWind speed, extreme rain, and a “thunderstorm” code from the weather servicewind 70 km/h · rain 50 mm/hrTrees bending in a strong gust.
TsunamiHow fast the sea level changes (a coastal tide gauge)50 cm changeA bathtub sloshing when someone drops in.

Earthquake: a spike against calm

Ground always shakes a tiny bit (trucks, footsteps). So the detector does not use a fixed number. It compares the short-term average (the last few readings) with the long-term average (the usual level). If the ratio jumps above 3, something unusual is happening. This idea is called STA/LTA and is a classic in real seismology.

Tsunami: only trust the sea

A tsunami warning is serious, so we made this detector strict. It reads a coastal sea-level value only. A river or pond level is not accepted as evidence, because a rising river is a flood, not a tsunami.

6Working with and without the internet

This is the heart of the design. The alarm must never depend on the cloud, so the internet is treated as a bonus.

While offline, every reading is saved to the local database with a flag “not synced yet”. When the program notices the internet is back, it goes through those saved rows and marks them synced. That way nothing recorded during the outage is lost.

7What the user sees

The phone-style web app has five screens. The screen asks your phone for its position, sends it to the backend, and shows the answer.

  • Home: the risk level right now, each of the four dangers, the live sensor numbers and the local weather.
  • Shelter: nearby safe places (hospitals, community centres, fire and police stations, stadiums, tagged shelters) from OpenStreetMap, within 5 km, widening the search if none are found.
  • SOS: a big button that calls the national emergency number, plus police, fire and ambulance numbers.
  • Prediction: charts of recent water and shaking readings. They show activity trends. They do not predict earthquakes.
  • Report: the history of past alerts.

8Putting it in a box: the zip file

Most programs fail on someone else’s computer because they need other software installed first. We avoided this by putting everything inside one folder: our code, the libraries, and a small copy of Python itself.

  1. Unzip DisasterWatch.zip anywhere.
  2. Double-click START.bat.
  3. The browser opens at http://localhost:5000.

The history database is created inside the folder’s data directory, so it is saved between runs. The zip does not include the private .env file, where the AI service key lives. The build script build_portable.py rebuilds the zip after any change.

Problems we found and fixed

  • Storm and tsunami seemed “not working”. The server running on the screen had started before those files were added, so it was running old code. Restarting fixed it.
  • The manual test form dropped the new values. It ignored wind speed and sea-level change, so storm and tsunami could not be triggered by hand. We added both fields.
  • Missing libraries. A fresh Python had none of the needed packages. The zip now carries them.
  • Dead files. An old desktop dashboard and its scripts were no longer used, so we removed them.

10Limits: what this is not

Please read this part. This is a learning and demonstration project. It is not an official warning system, and nobody should rely on it to stay safe.

  • Sensor data is simulated. Real sensors would need real hardware (a setting exists for it, but we did not test hardware).
  • SMS is only printed. The program writes “SMS to …” in its log; it does not yet send a real text message.
  • Detection is rule-based. Fixed limits can miss slow dangers or fire on a faulty sensor. Limits should be tuned for each place.
  • The live earthquake check only sees shaking. It cannot say how strong the quake was or how far away it started.
  • Shelter results are unverified. They come from a public map and may be out of date.
  • Alerts show only while the app is open. There is no background phone notification service.
  • No login. Anyone who can reach the server can read its data, so it should stay on a trusted network.
  • The zip is for Windows (64-bit) only.

11What we could do next

  • Connect real sensors and a real SMS service.
  • Add true phone notifications so alerts arrive when the app is closed.
  • Use several stations to confirm an alert before sounding it, which lowers false alarms.
  • Add a login and host the server so it can be used from anywhere.
  • Translate the app and the emergency numbers for other countries.

12Word list

Offline-first
Designed to work with no internet, and to use it only as a bonus.
Rule-based
Decisions come from clear if-then rules, not a black box.
STA/LTA
Short-term average divided by long-term average. It spots sudden shaking.
Tide gauge
A device on the coast that measures the sea level.
API
A menu of questions one program can ask another, for example “what is the risk?”.
SQLite
A whole database kept in one file.
LLM
A language model, the kind of AI that writes sentences.
False alarm
An alert when there is no real danger.
